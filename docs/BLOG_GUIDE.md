# CJY 知识工作台：博客写作使用指南

## 一、推荐打开方式

日常使用请打开：<https://cjy0722.github.io/cjy-knowledge-workbench/#blog>

这个网页长期在线。电脑上只需要运行本地桥接，不需要运行开发服务器。`127.0.0.1:3000` 是开发地址，关闭开发终端后就无法继续访问。

## 二、首次准备

### 1. 安装项目

```powershell
git clone https://github.com/CJY0722/cjy-knowledge-workbench.git
cd cjy-knowledge-workbench
npm install
```

### 2. 启动桥接

在 PowerShell 中执行：

```powershell
npm run bridge -- --vault "E:\自生长知识库"
```

桥接窗口需要保持运行。每位使用者连接自己的 Obsidian 后，再在工作台“设置”中填写自己的 DeepSeek API Key。密钥只保存在当前桥接进程内存中，关闭桥接即清除；不要把真实密钥写进源码、Markdown、截图或 GitHub。

也可以在启动桥接前临时设置 `DEEPSEEK_API_KEY` 环境变量，但公开项目不附带任何人的密钥：

```powershell
$env:DEEPSEEK_API_KEY = "YOUR_API_KEY_HERE"
npm run bridge -- --vault "E:\自生长知识库"
```

### 3. 连接 Obsidian

1. 打开公网工作台并进入“博客写作”。
2. 在“开始前检查”中点击“连接 Obsidian”。
3. 核对知识库名称和网页来源，点击“允许连接”。
4. 返回工作台后打开“设置”，填写自己的 DeepSeek API Key 并点击“保存到本机”。
5. 确认博客页显示“Obsidian 已连接”和“DeepSeek 已配置”。

授权只在当前标签页会话中保存。关闭标签页或重启桥接后，需要重新连接。

## 三、从知识库生成 AI 初稿

请按以下顺序操作：

1. 写作方式选择“AI 从知识源写”。
2. 材料类型选择“Markdown / 代码”。
3. 在“写作材料”中输入关键词并搜索，然后点击一篇笔记。
4. 修改“文章重点”和“本次要求”。
5. 点击“确认重点”；如果确实不需要重点约束，可点击“明确跳过讨论”。
6. 点击“执行五类预检”。即使没有命中，也会记录为已完成。
7. 点击“AI 生成初稿”。在确认窗口核对 DeepSeek 状态，然后点击“同意并生成”。
8. 在编辑区检查并修改生成结果。
9. 点击“审核检查”。如果出现阻塞项，点击“修正阻塞项”，DeepSeek 会按审核结果改写并自动复检；仍有阻塞时可人工修改后再次审核。
10. 点击“DeepSeek 去 AI 味”，检查改写后的事实、代码、链接和表达。此操作不会自动保存或通过人工检查。
11. 审核无阻塞后点击“确认后写入”，把当前版本保存到 Obsidian。
12. 在“人工确认”中选择“已完成人工表达检查”或“明确跳过”，再点击“确认文章定稿”。
13. 生成推广文案或五平台物料。

选择或更换知识源后，系统会清除旧的重点确认和预检结果。因此正确顺序是：先选知识源，再确认重点和执行预检。

## 四、自己创作

1. 选择“自己创作”或点击“新建原创”。
2. 输入标题和 Markdown 正文，也可以导入 `.md`、`.markdown` 或 `.txt` 文件。
3. 确认重点并执行五类预检。
4. 审核；需要时使用“修正阻塞项”和“DeepSeek 去 AI 味”，复核后保存并定稿。
5. 生成五平台物料。

自己创作正文默认不调用 DeepSeek；只有主动点击“修正阻塞项”或“DeepSeek 去 AI 味”时才会调用。预检、打开草稿、保存和生成平台物料仍需连接本地桥接。

## 五、修改已有文章

1. 选择“修改已有文章”。
2. 点击“导入 Markdown”或“打开已有文章”。
3. 填写修改要求。
4. 确认重点并执行预检。
5. 点击“AI 辅助修改”，确认后生成完整修改稿。
6. 审核并保存新版本。同名文件覆盖前会再次确认，旧版本会归档。

## 六、PDF、板书和图片材料

1. 材料类型选择“PDF / 板书 / 图片”。
2. 先自行渲染或执行 OCR。
3. 在“渲染 / OCR 核验记录”中填写核对过的页码、图示要点或笔记路径。
4. 勾选“我已真正核对图像”。
5. 再确认重点、执行预检并生成或审核。

工作台不会把一个复选框冒充 OCR，也不会自动把未经核对的图片内容写成事实。

## 七、多平台发布

- CSDN、掘金：生成标准 Markdown。
- 知乎、微信公众号：生成富文本兼容稿。
- 小红书长文：生成去除 Markdown 标记的纯文本。
- 小红书图文：按内容拆成 1080 × 1440 的 PNG 图卡。

点击“生成五平台物料”后，可分别复制标题和正文，并打开官方编辑器。账号登录、图片重新上传、封面、标签和最终发布都需要人工完成。

## 八、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 显示“等待本地桥接” | 桥接未启动或当前标签页未授权。启动桥接后点击“连接 Obsidian”。 |
| 显示“DeepSeek 未配置” | 打开工作台“设置”，填写自己的 DeepSeek API Key 并点击“保存到本机”。 |
| DeepSeek 返回余额不足 | 登录自己的 DeepSeek 账户检查 API 余额；不同使用者不能共用项目维护者的密钥。 |
| 提示 DeepSeek API Key 无效或已失效 | 工作台会自动清除无效密钥。请到 DeepSeek 官方控制台撤销旧密钥、创建新密钥，再回到“设置”填写；不要把密钥发到聊天或截图中。 |
| AI 生成提示先选择知识源 | 先在“写作材料”中搜索并点击一篇笔记。 |
| AI 生成提示先预检 | 选择材料后重新确认重点，再执行五类预检。 |
| 图片材料无法审核 | 填写核验记录并勾选“我已真正核对图像”。 |
| “修正阻塞项”没有出现 | 先点击“审核检查”；仅在存在阻塞项时显示修正按钮。 |
| 去 AI 味或阻塞修正无法执行 | 确认本地桥接已连接、DeepSeek 已配置，并且已完成预检、重点确认和材料核验。 |
| 自动修正后仍有阻塞项 | 按复检结果人工修改，再点“审核检查”；系统不会编造缺失资料来强行通过。 |
| 无法确认定稿 | 必须先保存最新草稿、通过审核，并完成或明确跳过去 AI 味检查。 |
| `127.0.0.1:3000` 无法访问 | 这是开发地址。改用公网工作台，或另开终端运行 `npm run dev -- --hostname 127.0.0.1 --port 3000`。 |

## 九、安全说明

- DeepSeek 密钥只发送到已配对的 `127.0.0.1` 本机桥接并保存在进程内存中，关闭桥接即清除。
- GitHub 项目不包含维护者或任何使用者的密钥；每位使用者必须填写自己的密钥。
- 网页不会读取或保存发布平台密码、Cookie 或 Token。
- GitHub Pages 不保存知识库内容。
- 最终写入 Obsidian 和发布到外部平台前都保留人工确认。
